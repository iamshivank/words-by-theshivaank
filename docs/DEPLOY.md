# Deploying Words (free tier)

| Piece | Host | Config in repo |
|---|---|---|
| Frontend (`frontend/`, Vite + React) | Vercel (Hobby, free) | `frontend/vercel.json` |
| API (`backend/`, Spring Boot, Java 25) | Render (free web service, Docker) | `render.yaml`, `backend/Dockerfile` |
| Database and uploaded images | Neon (free) | Flyway migrations |

Vercel forwards `/api/*`, `/uploads/*`, `/rss.xml`, `/sitemap.xml` and `/robots.txt` to Render. The browser only
ever talks to the Vercel domain, which is what lets the `SameSite=Strict` session cookie work. Never point the
frontend straight at the Render URL (leave `VITE_API_URL` unset).

Uploaded images are stored in the database (`media.data`, migration V7), not on disk, because Render's free
plan has no persistent disk. Nothing is lost on redeploy or restart. Keep an eye on Neon's free storage limit
if you upload many large photos.

## 1. Backend on Render

1. Merge the deploy changes into `main` (Render builds the default branch).
2. <https://dashboard.render.com> → sign in with GitHub → **New → Blueprint** → pick `words-by-theshivaank`.
   Render reads `render.yaml` and proposes one free web service called `words-api`.
3. Fill in the values it asks for:

   | Name | Value |
   |---|---|
   | `SPRING_DATASOURCE_URL` | Neon connection string, **direct** host (no `-pooler`), pasted as is |
   | `OWNER_EMAIL` | your login email |
   | `OWNER_PASSWORD_HASH` | bcrypt hash (paste as is, `$` signs included) |

   `JWT_SECRET` is generated by Render. `APP_PUBLIC_URL` defaults to `https://words-by-theshivaank.vercel.app`;
   change it if your Vercel URL is different. `PORT` is set by Render and read by the app.
4. **Apply**. The first Docker build takes several minutes (Maven downloads everything once).
5. Open `https://<service>.onrender.com/api/v1/auth/me`. It should show `{"authenticated":false,...}`. If the
   deploy fails, the logs print a boxed "Words cannot start" message naming the variable that is wrong.

### Free plan behaviour

Render stops a free service after 15 minutes without traffic, and the next request waits while it starts again
(around a minute for Spring Boot). Two ways to live with it:

1. Accept it: the first visitor after a quiet period waits.
2. Keep it awake: a free monitor such as UptimeRobot or cron-job.org calling
   `https://<service>.onrender.com/api/v1/auth/me` every 10 minutes. One always on service fits inside Render's
   750 free hours a month.

## 2. Frontend on Vercel

1. <https://vercel.com/new> → import the repo.
2. **Root Directory**: `frontend`. Framework preset **Vite** (auto detected), build `npm run build`, output `dist`.
3. **Environment Variables**: `BACKEND_URL` = `https://<service>.onrender.com` (with `https://`, no trailing
   slash). Do **not** add `VITE_API_URL`.
4. **Deploy**, and note the production URL.

If you change `BACKEND_URL` later, redeploy on Vercel: `vercel.json` substitutes it at build time.

## 3. Check it works

1. `https://<vercel-url>/` loads, and reloading a deep link like `/writing/...` does not 404.
2. `https://<vercel-url>/api/v1/auth/me` returns JSON (the proxy works).
3. Sign in at `/login`, reload, and confirm you are still signed in (the cookie works).
4. Upload an image in the editor, trigger **Manual Deploy** on Render, and confirm the image is still there.
5. `https://<vercel-url>/robots.txt` ends with `Sitemap: https://<vercel-url>/sitemap.xml`.

## Custom domain (optional)

Vercel → Project → **Settings → Domains** → add it and follow the DNS steps. Then set
`APP_PUBLIC_URL=https://yourdomain.com` on Render.

## Day to day

`git push origin main` redeploys both. New Flyway migrations run on the API's next start. Vercel previews use the
same `BACKEND_URL`, so they talk to the production API and data. Locked out? Set `OWNER_RESET_FROM_ENV=true` on
Render for one deploy, then remove it.

## Troubleshooting

| Symptom | Likely cause |
|---|---|
| Render log: "configuration needs attention" | A required variable is missing or malformed; the message names it. |
| Render log: Flyway / pooler error | `SPRING_DATASOURCE_URL` uses the `-pooler` host. Use the direct one. |
| Render log: out of memory / exit 137 | 512 MB is tight; check `JAVA_TOOL_OPTIONS` is set as in `render.yaml`. |
| Site loads but every API call 404s or returns HTML | `BACKEND_URL` missing on Vercel or has a trailing slash. Redeploy after fixing. |
| First request after a quiet period fails or takes a minute | Render free instance waking up. See "Free plan behaviour". |
| Login works but you're signed out on reload | The site is calling Render directly; make sure `VITE_API_URL` is not set. |
| Saving returns 403 "Invalid CORS request" | `APP_PUBLIC_URL` on Render doesn't match the URL in the browser bar. |
